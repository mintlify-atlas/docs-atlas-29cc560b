pyxctsk is a Python implementation of XCTrack's task format for paragliding and hang gliding competitions. It enables parsing, manipulation, conversion, and visualization of XCTrack task files — the `.xctsk` files used to define competition routes — while also serving as an open-source reference implementation of the FAI Sporting Code S7F distance calculations, so that a task's published distance is reproducible by anyone rather than depending on which device the task committee used.

## What are .xctsk files?

An `.xctsk` file is the task format used by [XCTrack](http://xctrack.org/), the most widely used flight computer app for paragliding and hang gliding competitions. It describes a complete competition course: an ordered list of **turnpoints** (each a named waypoint paired with a cylinder radius), the timing rules for the speed section (SSS to ESS), and the goal definition. Tasks are exchanged between pilots, task committees, and scoring software using both the full JSON format (`.xctsk` files) and a compact **QR code** format — either as an `XCTSK:` or `XCTSKZ:` URL string small enough to print or display as a QR code that works in direct sunlight.

pyxctsk implements the complete [XCTrack Competition Interfaces specification](http://xctrack.org/Competition_Interfaces.html): both task formats, both QR schemes, manufacturer extensions, and all documented fields. All 25 reference tasks generated by tools.xcontest.org round-trip byte-identically.

## Two entry points

pyxctsk is available as both a **Python library** and a **CLI tool**, both installed together via `pip`:

- **Library** — Import `load_task`, `parse_task`, `Task`, `DistanceReport`, `render_task`, and more from the `pyxctsk` package. All public names are available from the top-level `pyxctsk` namespace.
- **CLI** — The `pyxctsk` command accepts `.xctsk` files, `XCTSK:`/`XCTSKZ:` strings, and QR code images, and converts or measures them from the command line.

## Key capabilities

**Parse and convert tasks** — `load_task()` reads any supported input from a file path. `parse_task()` reads any payload (JSON string, `XCTSK:` URL, or QR image bytes) without touching the filesystem. `render_task()` writes a `Task` out as JSON, KML, GeoJSON, a QR code PNG, or a compact `XCTSK:` string.

**Typed data model** — Core objects (`Task`, `Turnpoint`, `Waypoint`, `SSS`, `Goal`) are plain dataclasses with enum-constrained values. `Task.validate()` checks the spec's structural rules (TAKEOFF only first, SSS and ESS exactly once, SSS before ESS). Pass `strict=True` to `parse_task()` or `load_task()` to turn violations into a `TaskValidationError` at parse time.

**FAI S7F distance calculations** — `DistanceReport.from_task()` computes both distances that FAI Sporting Code Section 7F §7.2 defines — the optimized task distance (launch to goal) and the speed section distance — together with every reading of the undefined "distance through centres" that task boards conventionally publish. Results are rendered as structured JSON (`.as_dict()`) or plain text (`.as_text()`).

**QR code support** — pyxctsk can read and write both the `XCTSK:` (plain) and `XCTSKZ:` (zlib-compressed) QR payload formats. Reading and writing these strings requires only the core install. Rendering a PNG image or reading a QR code from an image requires the `[qr]` extra.

## Installation extras

```bash
pip install pyxctsk          # core library and CLI
pip install "pyxctsk[qr]"    # adds PNG QR code output and QR image input
```

The **core** install covers everything except QR image I/O: parsing `.xctsk` files, all format conversions, `XCTSK:`/`XCTSKZ:` string generation, KML, GeoJSON, and FAI S7F distance calculations. The **`[qr]` extra** adds Pillow, qrcode, and zxing-cpp for rendering QR codes to PNG files and reading them back from images.
